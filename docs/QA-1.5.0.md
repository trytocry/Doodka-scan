# QA QR Duplicator 1.5.0

Дата: 13.11.2026, Europe/Moscow. Проверена готовая Windows x64 сборка `release/win-unpacked/QR Этикетка.exe`.

## Вердикт

**Проверка пройдена. Блокирующих дефектов в проверенном объёме не обнаружено.** Три независимых desktop-теста прошли за 16,9 с. Production-код QA-агент не изменял.

Команда: `npx playwright test tests/qa-desktop.spec.js --workers=1 --output=qa-artifacts/test-results`.

Основной агент отдельно сообщил успешный регрессионный прогон: 6 unit-тестов обновлений, 2 unit-теста диагностики и 14 Playwright-тестов. Это отдельный прогон, а не результат команды QA выше.

## Что подтверждено непосредственно QA

- Реальный EXE запущен с отдельным профилем. `app.getPath('userData')` совпадает с переданным `--user-data-dir`; открытая установленная версия пользователя не затрагивалась.
- Системное меню отсутствует (`Menu.getApplicationMenu() === null`), блок `.maker` отсутствует в рабочем окне.
- У основных и вторичных кнопок меняется оформление при hover; pressed отличается от обычного состояния. Disabled-кнопка сохраняет оформление при наведении.
- Изображение PNG действительно помещалось в системный буфер средствами Electron 45, затем передавалось через `Control+V`. QR распознан, PDF стал доступен. Это не синтетический DOM `paste`.
- Перед тестом все элементы и типы буфера материализованы через `clipboard.read()` / `ClipboardItem.getType()`. Исходные элементы восстановлены атомарным `clipboard.write()` в `finally`; содержимое буфера не выводилось в логи.
- Вставка изображения при фокусе в числовом поле не меняет текущий код.
- При окне 1160 × 900 кнопки «Печать» и «Скачать PDF» находятся в видимой рабочей области. При ширине 440 px нет горизонтального переполнения.
- Размер 16 мм и 7 копий восстанавливаются после полного закрытия/перезапуска EXE с тем же профилем; промежуточное недопустимое значение 501 не затирает последнюю корректную пару. Счётчик страниц восстановлен до загрузки фото.
- «Сбросить» сохраняет 18 мм / 1 шт. после следующего перезапуска. В записи localStorage содержатся только `version`, `size`, `copies`.
- Чекбокс автообновлений включается и выключается через UI, настройка действительно записывается в JSON профиля; выключенное состояние сохраняется после перезапуска. В тестовом профиле автоматические проверки изначально выключены, реальные обновления не скачивались.
- Диагностика использует действующий порт передачи фото и не закрывает его: после проверки страница передачи продолжает отвечать HTTP 200.
- При пустом списке принтеров диагностика показывает отдельное предупреждение; PDF остаётся доступен, а подтверждение печати блокируется с объяснением.
- Локальный запрос не объявляется подключением телефона: интерфейс явно сообщает, что доступ через брандмауэр нельзя подтвердить с этого компьютера.

## Визуальная проверка

Осмотрены `qa-artifacts/main-ready.png`, `main-narrow.png`, `readiness.png`. Текст читаем; состояния управления различимы; окно диагностики прокручивается, не меняя основную страницу. Блок автообновлений может находиться ниже первого экрана на невысоком окне; основные операции с наклейкой доступны без прокрутки.

## Исправление тестового окружения

Первый прогон диагностического теста выявил не дефект программы, а ограничение Playwright `page.request` для Electron: автоматически сформированный User-Agent содержал кириллическое имя приложения и отклонялся HTTP-клиентом. Для проверочного запроса задан ASCII User-Agent `QR-Duplicator-QA`; повторный прогон всех трёх тестов прошёл.

## Границы подтверждения

- Физическая печать, калибровка и подключение TSC TE200 не выполнялись. Для сценария отсутствующего принтера список Windows-принтеров подменён пустым.
- Не выполнялась установка на чистый другой компьютер/виртуальную машину. Автономность распознавания/PDF покрыта отдельными регрессионными тестами основного агента.
- Не выполнялись установка драйвера, изменение брандмауэра, проверка реального телефона через Wi-Fi или изменение системных разрешений.
- Драйвер TSC не входит в дистрибутив: интерфейс направляет на официальный источник. Универсальная готовность любого оборудования не заявляется.
- Блокировка будущих фоновых проверок и установки при отключённом чекбоксе покрыта unit-тестами контроллера обновлений основного агента. QA проверил UI и реальное сохранение между запусками; реальная загрузка/установка обновления не инициировалась.

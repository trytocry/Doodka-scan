# Повторная проверка Ctrl+V в 1.5.3

Дата: 13.11.2026, Europe/Moscow.

Локальная команда: `npx playwright test tests/qa-desktop.spec.js --workers=1 --output=qa-artifacts/paste-investigation`.

Результат: **2 passed, 1 failed**. Сохранение параметров/автообновлений и диагностика передачи прошли. Тест Ctrl+V не дошёл до записи PNG и клавиатурной вставки: системная предварительная проверка десять секунд получала `Windows OpenClipboard: error 5` (`Access denied`). Этот повторный прогон не подтверждает приёмку реальной вставки в текущем окружении.

## Наблюдения

- Первоначально тест падал на пустом `#decoded`. Дополнительная проверка установила, что `clipboard.has('image/png')` возвращает false сразу после записи тестового PNG, ещё до Ctrl+V.
- Фокусировка окна перед записью с подтверждением `BrowserWindow.isFocused() === true` результата не изменила.
- `clipboard.read()` возвращал элемент с пустым списком MIME. При этом независимый Windows API сообщал шесть форматов в буфере.
- Независимый WinForms `Clipboard.GetDataObject()` также завершался ошибкой. Win32 `OpenClipboard(NULL)` возвращал false и код 5. `GetOpenClipboardWindow()` возвращал нулевой handle; конкретный блокирующий процесс не установлен.
- Причина недоступности системного буфера (временная блокировка или ограничения окружения) не установлена. Чужие процессы и системные разрешения не изменялись. Содержимое буфера не выводилось.

## Изменения теста

- Добавлена независимая предварительная проверка Windows с ограниченным ожиданием. Если буфер недоступен, тест завершается до его изменения с точной причиной.
- Непустой системный буфер с пустым результатом чтения Electron не трактуется как пустой: запись PNG не выполняется, чтобы не потерять исходные данные.
- После записи проверяется реальное наличие PNG. Настоящее нажатие Ctrl+V и проверка распознанного содержимого сохранены; `skip` и искусственного успешного `paste` нет.
- Добавлены метаданные событий клавиатуры/вставки для диагностики возможного следующего сбоя, без содержимого буфера.
- Production-код и сборка не менялись. `git diff --check` пройден.

Предыдущие успешные проверки Ctrl+V не отменяются, но не заменяют этот результат. Для приёмки текущей версии нужен успешный прогон на среде с доступным системным буфером, например на отдельном Windows CI runner.

Использован документированный асинхронный API Electron `ClipboardItem` / `clipboard.read()` / `clipboard.write()`: [официальная документация](https://www.electronjs.org/docs/latest/api/clipboard).

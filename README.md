# Doodka-scan / QR Этикетка

Программа для Windows: фотография QR или Data Matrix → наклейки 20 × 20 мм → PDF или печать. Фото можно выбрать на компьютере или передать с iPhone/Android по локальной сети.

## Установка и обновления

Скачайте **QR-Etiketka-Setup-…-x64.exe** из [последнего релиза](https://github.com/trytocry/Doodka-scan/releases/latest) и установите его один раз. Установка выполняется для текущего пользователя Windows, без требования прав администратора.

- Windows 10/11 x64.
- Проверка обновлений запускается через 15 секунд после открытия и повторяется каждые 6 часов.
- Новая стабильная версия скачивается автоматически. Она устанавливается при закрытии программы; можно также нажать «Перезапустить и обновить».
- Ручная проверка доступна внизу окна и в меню «Справка».
- Без интернета программа продолжает распознавать коды, создавать PDF и печатать.
- Установщик не подписан сертификатом издателя.

**Portable** запускается без установки, но автоматически не обновляется. Старые переносимые EXE 1.2.0 и ниже нужно один раз заменить версией Setup. Нельзя получить обновления в старом EXE, в котором механизм обновлений отсутствует.

## Фото с телефона

1. Подключите телефон и компьютер к одной локальной сети.
2. Нажмите «Добавить с телефона» в программе.
3. Сканируйте показанный QR камерой телефона.
4. На странице в браузере телефона нажмите «Сфотографировать» или «Выбрать из галереи».
5. Фото появится на компьютере автоматически. Проверьте тип и содержимое распознанного кода.

Если Windows запрашивает сетевой доступ, разрешите его для частной сети. Программа не меняет брандмауэр сама. Если страница не открывается, проверьте Wi-Fi, отсутствие изоляции клиентов/гостевой сети и при необходимости выберите другой адрес компьютера в окне передачи.

Ссылка действует 15 минут и отключается при закрытии окна передачи. Фото передаётся непосредственно на компьютер, без внешнего сервера. Поддерживаются JPG, PNG и WebP до 25 МБ; HEIC преобразуется на телефоне, если его браузер умеет открыть такой файл.

## PDF и печать

Укажите размер кода с белым полем (8–20 мм) и количество (1–500). Каждая этикетка занимает отдельную страницу 20 × 20 мм.

Для печати выберите установленный в Windows принтер и откройте системный диалог. Проверьте носитель **20 × 20 мм**, масштаб **100%**, число копий в системном диалоге **1**: нужное количество этикеток уже подготовлено страницами. Для TSC TE200 нужен установленный драйвер и калибровка под ленту.

Код выравнивается по целым точкам печати 8 точек/мм. Фактический размер может быть меньше выбранного и показывается в интерфейсе. Белое поле составляет минимум четыре модуля. Слишком плотный код не экспортируется, если модуль получился меньше двух точек.

Data Matrix остаётся Data Matrix: сохраняются исходная матрица, служебные признаки GS1 и разделители. Перед использованием матрица повторно считывается и сравнивается с исходными данными. QR со специальными сегментами, которые нельзя безопасно восстановить, отклоняется.

## Разработка

Нужен Node.js 22. Команды приведены для Windows:

```powershell
npm ci
npm ci --prefix desktop
npm run dev
```

Для сборки настольной версии и проверок:

```powershell
npm run desktop:dir
npx playwright install chromium
npm test
npm run desktop:package
```

Сборка интерфейса находится в `dist/`, установщики — в `release/`. Зависимости и локальные сборки в Git не включаются. `npm test` проверяет обновления, QR/Data Matrix, сохранение данных маркировки, PDF, мобильную передачу и параметры печати. Тесты не отправляют задания настоящему принтеру.

## Выпуск новой версии

1. Измените версии в `package.json` и `desktop/package.json`, обновите оба lock-файла через `npm install --package-lock-only` и `npm install --prefix desktop --package-lock-only`.
2. Обновите `RELEASE_NOTES.md` и `CHANGELOG.md`, закоммитьте и отправьте изменения.
3. Создайте тег, совпадающий с версией настольного приложения, например `v1.3.1`, и отправьте его:

```powershell
git tag v1.3.1
git push origin main
git push origin v1.3.1
```

GitHub Actions запускает тесты, собирает Setup и Portable, загружает EXE, blockmap и `latest.yml` в черновик релиза и лишь затем публикует его. Приложения увидят новую стабильную версию автоматически. Не перезаписывайте опубликованный релиз: исправления выпускаются новым номером версии.

Токены GitHub не входят в программу и исходники. Workflow использует штатный `github.token` только во время публикации. Пользователю приложения вход в GitHub не нужен.

Физическая печать на TSC TE200 и работа камеры конкретного телефона проверяются на месте. Автотесты проверяют данные и раскладку, но не заменяют контрольную распечатку.
